# Core Index

Core describes how Randhu thinks and works as a developer. It does not define a project's visual identity, stack, API, or business rules.

## Modules

- `developer-profile.md`: identity, focus, and quality expectations.
- `engineering-principles.md`: clean code, maintainability, refactoring, abstraction, and edge cases.
- `ai-collaboration.md`: intent, requirement interpretation, evidence, autonomy, and communication.
- `ui-ux-principles.md`: global UI quality standards and decision framework.
- `design-system-intelligence.md`: design-system discovery, Visual DNA, tokens, component architecture, and frontend quality gates.
- `frontend-and-fullstack.md`: frontend structure, state, data fetching, API, and backend boundaries.
- `api-backend-intelligence.md`: contract-first API work, backend architecture, data integrity, authorization, resilience, and testing.
- `performance.md`: technical performance and perceived experience.

Load only the modules relevant to the active task through [the task map](../runtime/task-map.md). The session baseline remains the concise global entry point.

## Boundary test

Put a rule in DevBrain only when it describes how Randhu thinks and applies across projects.

Put a rule in project context when it describes how one project works, including:

- target users and business goals;
- stack, package manager, and libraries;
- colors, typography, radius, spacing, density, or visual direction;
- API endpoints, payloads, roles, permissions, and business flows;
- build/test/deploy commands and folder structure;
- sensitive files or repository-specific restrictions.
