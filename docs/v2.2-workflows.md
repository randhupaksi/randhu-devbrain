# DevBrain v2.2 Workflow Adoption

V2.2 adds project discovery, evidence-based debugging, and adaptive completion criteria. They are English Markdown workflows selected by outcome. The canonical entry remains the session baseline; seven standalone skills remain available through the existing adapters.

## When to select them

| Situation | Workflow and expected action |
|---|---|
| "Explain this unfamiliar repo; do not edit" | Project discovery, read-only findings and gaps |
| "Add this feature in a repo you have not seen" | Scoped discovery followed by the authorized implementation |
| "Change this known label" | Baseline and affected target; no broad discovery |
| "Diagnose why submission fires twice" | Debugging, read-only evidence and hypotheses |
| "Fix duplicate submission" | Debugging, safe reproduction, cause-driven correction and verification |
| "Is this task complete? Do not change files" | Definition of done, read-only coverage/evidence review |

The compressed commands `project-scan`, `safe-fix`, and `done-check` route to these procedures. Natural-language requests work through the task map; the commands are optional.

## Composition and context

Discovery follows the affected path outward until conventions, consumers, risks, and verification are sufficiently known. Debugging uses discovery only when context is missing, and testing-strategy only when test work becomes a substantial subtask. Completion review selects relevant evidence rather than loading every domain or running all checks. Reuse active context and avoid repeated reads or a full repository/skills scan.

A read-only review never silently implements findings. Tests, setup scripts, servers, and profiling commands may write files or contact services; inspect their behavior before treating them as read-only diagnostics. Low/medium-risk implementation continues under the baseline; unapproved high-risk actions remain gated. Unknown reproduction conditions must not be presented as a confirmed diagnosis.

## Adoption on Codex and Claude

Existing managed loaders point to this repository's baseline and task map, so both hosts can select the new workflows from the updated checkout. The bootstrap templates, installer, and installed skill content do not change in this release. A new session or explicit reload after the repository update avoids stale active routing. If DevBrain is cloned elsewhere, use the existing installer to point the host to that clone.

The source DOCX is a generalized v2.2 conceptual reference identified by its revision date and manifest hash. It is excluded from coding startup. Current behavior is defined by the maintained Markdown/YAML; historical audit reports retain their original counts and results.

## Acceptance and evidence

Eight new scenarios join the previous 30: discovery-only, tiny-task scope, discovery-to-implementation, debugging diagnosis-only, verified correction, unavailable reproduction, high-risk security correction, and completion review. Structural checks validate routing and suite shape. Live host behavior must be evaluated separately using synthetic fixtures and the [evaluation procedure](../evaluation/README.md).

Review the diff and content validator for this release. Installer integration needs rerunning when the installer, adapters, or source skill payload changes; those artifacts are unchanged here. No task log, persistent project map, or checklist document is created automatically.

The [validation report](v2.2-validation.md) records the completed structural/installer checks and current-session synthetic demonstration, with independent live-host evaluation marked NOT RUN.
