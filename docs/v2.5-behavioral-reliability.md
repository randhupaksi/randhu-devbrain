# DevBrain v2.5 Behavioral Reliability

V2.5 adds repeatable evaluation inputs and evidence contracts. It selects 12 representative cases from the existing 54-scenario suite: enterprise/marketing/design-system/architecture routing, a breaking API proposal, text-only Git listing, latest layout intent, handoff, stale-state resume, latest review mode, unsupported approval and validation honesty. Specialized performance/accessibility/testing cases remain in the full suite; select them when those skills change.

## Prepare and evaluate

Follow [the evaluation procedure](../evaluation/README.md). Fixture preparation creates 24 independent projects under ignored `local/`, one copy per case and host. Both copies receive identical project facts, AGENTS.md/CLAUDE.md and prompts. Evaluator scorecards stay outside the project context. Only the Git-list case gets an empty local fixture repository; no files are staged, committed or pushed.

Start an authorized fresh host session with the fixture project, its prompt, the current baseline and available skill metadata. Do not provide the expected outcome, scoring rubric, or full skills directory. Existing host configuration/authentication is not silently changed. A host runner may write caches/logs outside the fixture; establish an authorized session setup before using such a runner. Unattempted host cases remain NOT_RUN.

The continuity fixture intentionally fails the non-string test while preserving newer empty-input behavior and an unrelated user note. Fixing a generated copy is part of the authorized resume case. The tracked template retains the defect so future evaluations start from the same condition. Historical checks inside the fixture are labeled seeded data; do not present them as commands executed by the assistant.

## Score observed behavior

Each scorecard has six dimensions: routing/context, intent/precedence, worktree preservation, authorization, completion and validation honesty. Observed dimensions reference sanitized source-read, tool-call, file-change, check-result, response or environment observations. Record the host interface, model when actually known, date, initial fixture/prompt fingerprint and operational profile fingerprint.

- PASS requires evidence for every dimension and no critical failure.
- FAIL records an observed failed dimension or critical violation. It cannot be hidden as BLOCKED.
- BLOCKED records an attempted but incompletely scored case and the actual limitation.
- NOT_RUN records an unattempted case, with no invented observations or scores.

An existing-session walkthrough is labeled `existing_session`; it cannot establish native-host comparison. Two native records are comparable only when their initial fixture/prompt and profile fingerprints match and their scoring is complete. `both_pass` means both passed that observed case; it is not proof of universal parity or repeated reliability. Browser-unverified UI must remain incomplete for relevant visual dimensions.

The validator checks evidence structure, references, statuses, input comparability and heuristic privacy candidates. A human evaluator must assess whether the evidence actually supports each score. A well-formed fabricated record can still be untrue; schema validation does not authenticate evidence or independently observe a model.

## Scope and adoption

Evaluation scripts are manual maintenance tools. Normal coding keeps the same baseline, task routing, seven skills and bootstrap payload. Existing installations read the updated checkout; after an update, refresh DevBrain context according to its lifecycle. Evaluation does not require reinstalling skills or adding startup context. Installer dependencies remain unchanged.

Markdown/YAML defines operational v2.5. The conceptual source DOCX remains v2.2 with its existing hash; this upgrade does not request source revision. Refer to [the validation record](v2.5-validation.md) for executed checks, corrections and native-host limits. Add new scenarios only for observed failures or supported gaps; do not increase counts just to advertise coverage.
