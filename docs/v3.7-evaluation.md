# DevBrain 3.7 evaluation

DevBrain 3.7 uses the manifest skill inventory for both installers. The catalog still owns routing and handoffs. The PowerShell installer accepts a plain block list of lowercase skill IDs in `devbrain.yaml` and requires no YAML package. The simulated installer suite independently enumerates the source skills and compares both installed trees.

## Evidence by host

Run `node evaluation/skill-coverage.cjs` for the contract inventory by skill and host. Pass a prepared smoke batch's evaluator directory to include validated scorecards for the current release and profile. The report distinguishes cases outside the smoke suite, unattempted cases, blocked preflight, noncomparable session evidence, and reviewed session outcomes. Host matrix status remains separate from skill results. Preserve reviewer evidence in the local evaluator directory.

The smoke suite covers a full Git command list, a single commit subject, creative dashboard direction, and ordinary table sorting within the existing visual direction. The dashboard cases make it possible to check whether the skill activates only when the requested outcome calls for it.

## Matched comparison

The cases cover Git command listing, a creative dashboard, a linked public journey, ordinary and editorial copy, and a runnable fullstack slice. See the [benchmark procedure](v3.1-reliability.md#run-the-comparison) for running and scoring the cases.

- Use the same host build, model, effort, fixture, prompt, permissions, and resource limits within each comparison. Use separate fresh sessions. Keep treatment labels and rubric outside model context.
- Compare the no-DevBrain control, the committed v3.5 reference, and the candidate. The v3.6 worktree was not available as a committed reference. The guidance fingerprint recorded before the v3.7 update was `02793ed1631c380f2885f295d3fae3751c35f05448d51566ed2450bae621234f`.
