# DevBrain 3.3 Production Delivery

DevBrain 3.3 adds two specialists and an optional review for changes headed to production. The package contains 36 skills and 130 behavior scenarios.

| Requested outcome | Owner | Reviewable result |
|---|---|---|
| Design hosted resources or assess an infrastructure change | [Cloud infrastructure engineering](../skills/cloud-infrastructure-engineering/SKILL.md) | Topology and environment boundaries, ownership, resource lifecycle and data impact |
| Define service targets and recovery behavior | [Reliability engineering](../skills/reliability-engineering/SKILL.md) | User journey indicator, degradation policy, capacity evidence and recovery verification |
| Assess release readiness | [Production readiness review](../workflows/production-readiness-review.md) | Release judgment, stop conditions, recovery evidence and open risks |
| Review third-party software before execution | [Software supply chain](../safety/software-supply-chain.md) | Evidence for an adoption decision, with provenance and execution boundaries |

Capture operational facts where the project owns them. Use the [runtime operations template](../project-templates/PROJECT-RUNTIME-OPERATIONS.template.md) when a project lacks an existing source of truth. CI/CD still owns artifact promotion and rollout. Observability debugging owns diagnosis from actual telemetry. Skill selection is based on the artifact requested.

## Benchmark

Use the [benchmark suite](../evaluation/benchmark-suite.yaml) to compare a fresh host without DevBrain, the pinned 3.2 reference, and the 3.3 candidate. The suite has 17 cases. Four cover infrastructure lifecycle, reliability, release readiness, and third-party tooling. The [UI outcome rubric](../evaluation/ui-outcome-rubric.md) grounds existing visual cases in screenshots and interaction observations.

Prepare a full batch with `node evaluation/benchmark.cjs prepare 2`, or pass `prepare 1 <case-id>` for each new case to start with a smaller comparison. A full batch with two repetitions uses 204 slots. Follow the [comparison procedure](v3.1-reliability.md#run-the-comparison) for matched host settings and blinded scoring. Use the pinned 3.2 checkout's suite to reproduce the original 3.2-versus-3.1 benchmark.

## Evidence

Native Codex and Claude comparisons remain pending. Scenario definitions and prepared benchmark inputs establish what to evaluate. Release comparisons require observations from fresh host sessions and a review of their results.

Repository validation passed 4,280 checks across 272 files, including 130 scenario definitions. Skill validation passed 443 contracts across 36 skills. The Node test suite passed 39 tests, the content regression suite rejected 25 intentional defects and the skill regression suite rejected five. Simulated homes passed 93 installer assertions. Formatting and whitespace checks passed.

A read-only forward review of the two skill entrypoints held the database change when the plan showed replacement and distinguished confirmation send rate from recipient delivery. It also proposed an isolated drill for an ambiguous send result. This review used synthetic evidence and did not exercise a real infrastructure change, recovery drill, or native discovery.

The 17-case benchmark batch has 204 verified initial fingerprints across the two hosts, three conditions, and two repetitions. Results are `NOT_RUN` until an operator observes matched model sessions.
