# DevBrain v2.7 Candidate: CLI compatibility

V2.7 is a candidate focused on connecting DevBrain reliably to Codex CLI and Claude Code CLI. It keeps the existing file-based architecture: the installed host loader points to this checkout's session baseline, the task map selects relevant modules, and the host discovers skill metadata before a selected skill body is loaded.

This candidate does not add a DevBrain executable, daemon, global host settings, or a second runtime. Repository maintenance and simulated installation can be completed without installing Claude Code CLI. Native behavior must be reported separately for each host.

## Host behavior that matters

| Concern | Codex CLI | Claude Code CLI | DevBrain implication |
|---|---|---|---|
| User entrypoint | AGENTS.md in CODEX_HOME; default CODEX_HOME is under HOME | CLAUDE.md under HOME/.claude | Installer locations are host-specific; do not assume a shared filename or profile directory. |
| Project instructions | Root-to-working-directory AGENTS chain, including overrides | CLAUDE family or AGENTS family according to version and Project instructions setting | Confirm what the host actually loaded, especially when both filenames exist. |
| Skills | Names/descriptions are discovered; a selected SKILL.md supplies full instructions | Skill descriptions are available for selection; full skill content loads on invocation | Avoid a manual full-tree scan, but account for host-provided catalog metadata. |
| Sessions | Interactive, one-shot, and resumable runs have different context lifetimes | Interactive, -p, continue, and resume modes have different context lifetimes | A resumed session cannot count as fresh bootstrap evidence. |
| Safety | Instruction chain is separate from CLI sandbox and approval controls | CLAUDE.md is context; permission modes and sandboxing control tool access | DevBrain safety guides choices but does not replace host enforcement. |

Official references: [Codex instruction discovery](https://developers.openai.com/codex/guides/agents-md/), [Codex skills](https://developers.openai.com/codex/skills/), [Claude memory and instruction files](https://code.claude.com/docs/en/memory), [Claude skills](https://code.claude.com/docs/en/skills), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), and [Claude permissions](https://code.claude.com/docs/en/permissions).

For the native Claude run, the user requested Claude Sonnet 5 with medium effort. Pass model and effort as per-session CLI flags; do not save a new default in user settings.

## Candidate evidence

On 2026-10-28, the maintenance session observed Codex CLI 0.165.0 and Claude Code CLI 2.1.312.0. Claude was resolved from an active Claude Code process because the executable was not on PATH; a read-only auth-status command returned success. A fresh Codex one-shot requested `gpt-5.6-sol` at low effort; a fresh Claude one-shot requested `claude-sonnet-5` at medium effort. Both completed with exit code 0, returned relevant DevBrain loading guidance, and left their isolated project fixtures unchanged. The evaluator did not inject the baseline, and the Claude run disabled built-in/MCP tools and session persistence. The first Claude attempt timed out in the default sandbox; a subsequent authorized run completed. An earlier Codex prompt exposed the target file name and was discarded. The current neutral-prompt captures are recorded under ignored local/ and remain `needs_human_review`: neither CLI exposed a trustworthy trace identifying the exact instruction files read, and one short response cannot score the broader host matrix. The repository's prior v2.6 Codex evaluations manually supplied operational context, so they do not establish automatic bootstrap discovery.

Do not reinstall Claude Code or change user settings as part of repository maintenance. Installer integration and adapter checks verify target layout and payload, not live host behavior. Capture receipts remain in ignored local/ and contain no session identity or raw transcript. Both hosts are `partial` in the matrix; their project-scope, skill, resume, and permission cases remain unscored.

The complete host test contract is in [the CLI host matrix](../evaluation/cli-host-matrix.yaml). Its case definitions are plans until evidence is collected. Keep host version, mode, loaded-source evidence, context reads, skill selection, tool actions, and outcome separate for each run. Sanitize evidence before storing it under ignored local/.

## Completion criteria

- A fresh Codex CLI session discovers the installed entrypoint without manually injecting the baseline; one-shot and resume runs are scored separately.
- A fresh Claude Code CLI session confirms the user entrypoint and actual project instruction family; one-shot, continue, and resume are distinguished.
- Both hosts discover skill descriptions and load only the selected skill body and needed references.
- A fixture with both AGENTS.md and CLAUDE.md verifies Claude's configured behavior and avoids duplicated policy.
- Claude stale auto memory is treated as context, not as authority over the latest user request or current project evidence.
- Synthetic high-risk scenarios confirm that the assistant respects the boundary and that host permission controls remain enabled.
- The three UI cases deferred from v2.6 are evaluated independently with visual evidence where the fixture supports it.
- Missing-host cases remain NOT RUN or BLOCKED; structural parity does not become a claim of live cross-host compatibility.
