# DevBrain 3.4 Agent Engineering

DevBrain 3.4 adds two specialists for connecting agents to tools and evaluating how agents use them. The package contains 38 portable skills and 134 behavior scenario contracts.

| Requested outcome | Primary skill | Deliverable |
|---|---|---|
| Expose inventory lookup and reservation through MCP | [MCP server engineering](../skills/mcp-server-engineering/SKILL.md) | Tool schemas, compatibility assumptions, access policy enforcement and failure checks |
| Compare two support agents on answers and tool decisions | [Agent evaluation engineering](../skills/agent-evaluation-engineering/SKILL.md) | Matched run plan, scoring rubric, evidence requirements and report |

The MCP skill owns the protocol-facing contract. The provider adapter and identity policy retain their existing owners. Agent evaluation owns the comparison once the expected feature behavior is defined. Use the AI application skill for a change to the model feature itself. Consult the [skill selection guide](../runtime/skill-selection.md) for these boundaries.

## Benchmark

The [benchmark suite](../evaluation/benchmark-suite.yaml) compares a fresh host without DevBrain, the pinned 3.3 reference, and the 3.4 candidate. The 19 cases include the established UI, writing, fullstack and production work plus two cases for the new skills. Four activation and boundary contracts live separately in [scenarios.yaml](../evaluation/scenarios.yaml).

Use the [matched comparison procedure](v3.1-reliability.md#run-the-comparison) with the 3.4 suite and reference. Reproduce the earlier no-DevBrain, 3.2 and 3.3 comparison from the pinned 3.3 checkout with its own suite. This preserves the earlier fixture and profile fingerprints.

Start with a representative case before expanding to the full suite. Two repetitions create 228 slots.

```powershell
node evaluation/benchmark.cjs prepare 1 agent-evaluation-engineering
node evaluation/benchmark.cjs prepare 2
node evaluation/benchmark.cjs summarize <batch-id>
```

The report includes comparable counts, exclusions and improved, tied and regressed counts per dimension and host for each control. Score the outcome from artifacts and preserve observed routing or tool use as separate evidence. When observable, add optional `measurements` to a scored JSON card, keyed by `tool_calls`, `elapsed_ms`, `input_tokens` or `output_tokens`. Each measurement has a nonnegative integer `value` and a `source` that identifies the measurement method. Omit unavailable values. Only matched pairs with the same source for a metric receive a measurement delta, calculated as candidate minus control. Read the [UI outcome rubric](../evaluation/ui-outcome-rubric.md) for browser evidence.

## Release evidence

On 2026-11-21 the repository validator passed across 281 files and 134 scenarios. The skill-system validator passed 461 contracts. The Node suite reported 43 passes, including benchmark summary and measurement regressions. The content regression suite rejected 25 intentional defects across 27 assertions, and the skill-system regression suite rejected five. The installer passed 97 assertions using simulated homes. Prettier and Git whitespace checks passed.

The full 3.4 batch verified the initial fingerprints for 228 slots, all `NOT_RUN`. A separate one-repetition 3.3 batch prepared 102 unattempted slots before updating the checkout. CLI availability was observed for Codex CLI 0.171.0 and Claude Code 2.1.328. Authenticated isolation, native discovery and matched behavior results remain pending. The [host matrix](../evaluation/cli-host-matrix.yaml) records the requirements for that evidence.
