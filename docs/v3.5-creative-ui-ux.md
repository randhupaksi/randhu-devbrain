# DevBrain 3.5 — Creative UI/UX

DevBrain 3.5.0 is the creative UI/UX upgrade. It adds a dedicated skill for distinctive art direction and expressive interaction across interface types, while deepening guidance for brand-led landing pages and their supporting visitor routes.

The new skill applies to public and internal experiences alike: dashboards, admin tools, data products, application flows, editors, marketing pages, portfolios, and other interfaces can all be creative when the treatment fits the people and work involved.

## What changed

- Add Creative UI/UX as a new, self-contained skill for visual thesis, composition, visual grammar, hierarchy, typography, color, imagery, density, interaction, and motion.
- Add a creative direction playbook for operational dashboards, data-rich interfaces, editors, forms, narrative experiences, and other surfaces. It preserves task flow, data meaning, accessibility, and responsive behavior while allowing a distinctive visual identity.
- Expand Marketing & Portfolio UI/UX guidance for connected landing, information, action, confirmation, and recovery pages. Each route can share a product identity while using composition suited to its task.
- Clarify routing among Creative UI/UX, Enterprise UI/UX, Marketing & Portfolio UI/UX, and design-system ownership. Creative dashboards are explicitly in scope; operational behavior remains with its task owner.
- Connect the skill to the task map, skill catalog, UI workflow, core visual-direction guidance, current documentation, and host metadata.
- Keep reference use principle-led: the target's identity, copy, assets, palette, typography, page sequence, animation, and code remain distinct.

## Transferable design principles

The creative method synthesizes reusable lessons from inspected interface work without carrying over a source identity. A meaningful visual idea can connect distinct sections, while composition and density shift as content changes role. A recurring motif or transition earns its place by improving recognition or orientation; neither is required.

A vivid opening should still hand off to information and action screens that make exact facts and tasks easy to use. Related screens can share type roles, semantic color, shape language, and interaction feedback without repeating one layout. Responsive work can preserve that visual grammar with a different mobile composition.

Motion, large media, and scroll effects need static or reduced-motion alternatives, reasonable loading behavior, and a path to the task that does not depend on an effect finishing. Data-driven copy, prices, dates, and locale-dependent content must remain tied to their real source of truth.

The reference review focused on landing and supporting public-route source code. It did not render the site in a browser, so the report does not claim that source-level observations prove the final visual experience or usability.

## Skill ownership

Creative UI/UX owns cross-surface art direction and expressive interaction when that is a central outcome. Enterprise UI/UX owns operational task flow, data meaning, and application states. Marketing & Portfolio UI/UX owns public narrative, authentic proof, and visitor journeys. Select one primary owner by the requested outcome and add another only for a distinct artifact or decision.

The skill remains useful on its own. Its [entrypoint](../skills/creative-ui-ux/SKILL.md) links to the detailed [creative direction playbook](../skills/creative-ui-ux/references/creative-direction-playbook.md). The marketing skill's [public-experience reference](../skills/marketing-portfolio-ui-ux/references/creative-public-experiences.md) covers connected visitor routes.
