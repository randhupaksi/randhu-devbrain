# Editorial Patterns

Use these as contextual hypotheses. An isolated word, dash, passive sentence, three-item list, or formal phrase is not sufficient evidence of poor writing. Keep deliberate choices that serve the reader. Avoid replacing one repeated template with another.

| Problem | Editorial decision |
|---|---|
| Stock praise, ceremonial openings, repeated offers to continue | Start with the answer or artifact; acknowledge the user's situation when it helps |
| Abstract benefit claims or inflated significance | State the supplied fact, concrete consequence, or supported reason |
| An objection or dramatic contrast the reader never raised | State the useful claim directly; keep contrasts that explain a real trade-off |
| A heading followed by a sentence repeating the heading | Advance the explanation instead of restating the label |
| Every paragraph has the same length or sentence structure | Organize around ideas; adjust rhythm without enforcing randomness |
| Decorative triples, summary closers, or rhetorical questions | Keep only the items and transitions the meaning needs |
| Dense nouns, jargon, nominalizations, unnecessary passive voice | Prefer familiar verbs and a clear actor; retain domain terms and intentional neutrality |
| Synonym cycling for one technical concept | Keep the same precise term so readers can follow it |
| Vague authority such as 'experts agree' | Use an available source or flag the unsupported attribution; do not manufacture one |
| Excessive bold, emoji, fragments, headings, or bullets | Choose formatting for this artifact and audience, preserving requested conventions |
| Qualifications used as padding | Remove redundant hedges while retaining real uncertainty and limits |
| Explanations written around a diff rather than current behavior | Describe the current state; retain change history when that is the requested artifact |

## Original examples

Stiff: 'We are pleased to inform you that the export process has been successfully completed.'
Plain: 'Your export is ready.' Use that only when readiness is established. If processing continues, say 'Your export is processing.'

Inflated: 'This setting represents a pivotal advancement in workflow efficiency by allowing weekly report scheduling.'
Specific: 'You can schedule the report to run each week.' Do not imply that email delivery or another capability exists.

Overcompressed: 'Request failed. Retry.'
Useful: 'We could not load the report. Try again.' Offer retry only when it is supported and appropriate.

Uncertainty lost: 'The update may reduce loading time' must not become 'The update makes the page faster' without evidence.

Technical prose may need repeated exact terms and explicit exceptions. Legal, safety, scientific, and operational messages retain their precision and required detail. Humanization must not turn a consequential explanation into a slogan.
