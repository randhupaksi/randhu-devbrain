# Comparison design

Write a question, a comparison unit, and the expected evidence before opening results. Group matching runs by scenario, host and repetition. Hold initial state and material settings constant, vary treatment order and open a fresh session for each independent run. Record condition leakage or input drift and exclude affected pairs with their reasons.

Define objective checks for task completion, preserved files, scope and resource policy. Anchor subjective ratings to examples. For UI review attach screenshots with states and viewport sizes and use interaction evidence for behavior. If using a model grader, calibrate its ratings against human examples and check for preference based on response order, length or style. Keep its inputs bounded and evaluate artifacts using fixed criteria.

Record attempted actions from observable tool events and reconcile them with the artifact and final claims. A missing trace makes a process claim unobserved. Preserve safety failures independently of quality averages. Report wins, ties and losses per dimension and host, counts of unmatched cases, and the origin and unit of efficiency metrics. Report cost or token use only when the measurement is comparable. Rerun affected cases after targeted corrections.
