# Creative UI/UX

Create interfaces with a recognisable point of view and a clear reason for every visual and interactive choice. Creativity can help a product tell a story, clarify a complex workspace, make a tool inviting, or give an established workflow its own identity. It is useful across surface types; a dashboard can be expressive when its information and actions remain easy to read and use.

## When this skill applies

Use this skill when the user asks for creative, original, expressive, art-directed, immersive, brand-led, or visually distinctive interface work; when a substantial redesign needs a new visual concept; or when visual interaction and motion are central deliverables. It applies to public sites, portfolios, onboarding, forms, dashboards, admin tools, data products, editors, learning products, and other applications.

Do not activate it for routine bug fixes, ordinary spacing or copy changes, or a standard feature whose visual direction is not part of the requested outcome. A product category never forbids creative treatment; the user's goal, audience, content, evidence, and task determine how far to take it.

## Keep ownership clear

- Follow the latest user request and the active project's real behavior, identity, tokens, components, content, and constraints.
- This skill owns cross-surface creative direction: the visual thesis, composition, visual grammar, and expressive interaction decisions.
- Use enterprise-ui-ux when operational task flow, dense information, table/chart semantics, or application states are a primary deliverable. Creative treatment can remain central while those requirements stay intact.
- Use marketing-portfolio-ui-ux when public narrative, persuasive content, proof, or conversion flow is a primary deliverable. Keep a requested art-direction outcome visible across that journey.
- Use design-system-architect only for a distinct shared-token, component, or design-system contract. Use other specialists only when they own a separate behavior or artifact.
- Choose one primary owner from the requested outcome. A collaborator adds a distinct decision or handoff; it is not a mandatory pipeline.

## Work from evidence to a visual direction

For substantial creative work:

1. Understand who uses the interface, what they need to understand or do, which actions and information must lead, and what must remain unchanged.
2. Inspect the relevant project instructions, real content and data, design tokens, existing screens, media, component patterns, interaction states, responsive behavior, and implementation constraints. Separate facts from assumptions.
3. Form a concise design thesis that connects product meaning to a visual idea. A mood word such as “modern” or “premium” is not enough; translate the idea into visible decisions.
4. Choose a coherent visual grammar for hierarchy, composition, type, color, imagery, shape, density, and motion. Give each signature treatment a purpose and define where it should stop.
5. Apply that direction to the complete requested surface and its meaningful states, not only the first viewport. Recompose for smaller screens and preserve the real data and interaction contracts.
6. Refine the rendered interface when available. Check hierarchy, task clarity, visual distinctiveness, keyboard and touch behavior, contrast, responsive layouts, motion preferences, content overflow, and media fallbacks. Be clear about checks that were not possible.

Read [Creative Direction Playbook](references/creative-direction-playbook.md) for a substantial art-direction decision, creative product or dashboard treatment, motion-rich work, or a cross-surface visual family. Use only the relevant sections.

## Creative quality rules

- Make the direction specific to the product and content. Do not treat a trend, a style name, or a reference screenshot as a finished design brief.
- Use creativity to increase meaning, orientation, hierarchy, confidence, or delight. Do not let decorative novelty obscure a task, distort data, or claim capabilities the product does not have.
- Preserve useful information density. Expressiveness can come from typography, alignment, restrained color, pacing, composition, data visualization, meaningful interaction, or a considered signature motif; it does not require card grids, animation, or large hero text.
- Treat an existing visual system as evidence and a useful foundation. Adapt it deliberately; do not replace it merely to make a screen feel different.
- Do not copy a reference's identity, exact layout, copy, palette, assets, animation sequence, components, or code. Extract the principle that answers the design question and create a distinct expression for the target.
- Respect semantic HTML, visible focus, keyboard operation, readable contrast, reduced motion, real media loading limits, and the project's supported device and localization needs.
- Do not invent workflows, metrics, chart meaning, customer proof, permissions, business rules, or successful actions to make the design look complete.

Input: User intent, product and audience evidence, interface behavior and content, design-system context, and creative scope.

Output: A coherent visual thesis and interface whose expressive decisions serve the product, its users, and its actual tasks.
