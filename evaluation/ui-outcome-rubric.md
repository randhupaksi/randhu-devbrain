# UI Outcome Review

Use identical brief, starting fixture, sample data, browser settings and viewport sizes for each comparison. Mask the condition label. Keep the original benchmark scores and use this evidence to justify them.

| What to inspect | Observable evidence |
|---|---|
| Hierarchy and project visual identity | At desktop and narrow widths, identify the key task and first action. Check typography, density and tokens against the brief and existing UI. |
| Responsive behavior | Inspect reflow, long content, and whether the core task remains usable without clipped information or controls. |
| Interaction and recovery | Perform the primary journey, try the relevant empty or failure state, and verify that recovery keeps the user's progress where expected. |
| Accessibility | Use the keyboard through the journey. Inspect focus, names and important announcements where relevant. Check contrast and motion where they affect the surface. |
| Language | Inspect actual labels and status messages for accuracy, clear next actions and fit with the product's voice. |

Record screenshots with viewport and state, plus a short interaction trace and any unavailable evidence. A static screenshot supports visual observations. Use an actual interaction to substantiate behavior claims. Record material regressions in the affected benchmark dimension and report unobserved criteria separately.
